# WebAssistant как systemd-служба

## Канонический артефакт

Поддерживаемая целевая среда Linux:

```text
ALT Linux 10.1
```

Канонический сценарий упаковки:

```bash
./build/linux/package.sh
```

создаёт:

```text
<installerBaseName>-linux-x64-<VERSION>.zip
```

где `<VERSION>` равен точному содержимому файла `VERSION`, а `<installerBaseName>` берётся из фактических метаданных продукта. Публичное значение `installerBaseName` по умолчанию равно `WebAssistant`, поэтому без переопределения имя имеет вид:

```text
WebAssistant-linux-x64-<VERSION>.zip
```

Рядом создаются `.sha256` и `.provenance.json` для итогового ZIP.

ZIP содержит самодостаточное приложение `linux-x64`, `VERSION`, принадлежащий пакету `appsettings.json`, `install.sh`, `uninstall.sh` и `webassist.service`. Отображаемые метаданные, задаваемые при сборке, не меняют стабильный технический идентификатор systemd unit `webassist.service`.

## Конфигурация, принадлежащая пакету

Конфигурация выбирается во время упаковки:

```text
src/WebAssistant/appsettings.json существует
  -> сценарий копирует точные байты этого файла

файл отсутствует
  -> сценарий копирует build/common/default-appsettings.json
```

После формирования ZIP `appsettings.json` является неизменяемой частью пакета. `install.sh` не генерирует, не заменяет и не исправляет конфигурацию. Если упакованный `appsettings.json` отсутствует, пакет считается повреждённым и установка завершается с закрытием при неопределённости.

Без конфигурации конкретного окружения безопасный пакет содержит пустую карту `WebAssistant:FileSystem`, поэтому файловый обмен не получает автоматический физический корень. Именованные корни задаются явно, например:

```json
{
  "WebAssistant": {
    "FileSystem": {
      "archive": "/srv/webassistant/archive",
      "import": "/mnt/import"
    }
  }
}
```

Ключ `WebAssistant:FileSystem:RootDirectory` с допустимым абсолютным путём задаёт обычный логический корень с именем `RootDirectory`. Для другого публичного имени администратор явно изменяет конфигурацию. Полная структура и приоритет источников описаны в [`configuration.md`](configuration.md).

## Установка на ALT Linux 10.1

Распакуйте:

```text
<installerBaseName>-linux-x64-<VERSION>.zip
```

При публичном значении по умолчанию это `WebAssistant-linux-x64-<VERSION>.zip`.

Из распакованного каталога запустите:

```bash
sudo ./install.sh
```

Целевая рабочая станция не требует заранее установленного .NET Runtime, .NET SDK, NuGet или инструментов компиляции и сборки: payload приложения самодостаточен.

`install.sh` проверяет системные возможности: библиотеки ICU, GTK3 и SANE, команду `scanimage`, пакет `sane-airscan`, возможность загрузки его библиотеки и команду `airscan-discover`. Недостающие пакеты устанавливаются до запуска службы. Версия ICU определяется по доступным пакетам ALT, а не фиксируется заранее.

Если все зависимости уже установлены, apt-rpm не изменяется. Если чего-то не хватает, установщик выполняет штатные команды:

```text
apt-get update
apt-get install
```

Ошибка состояния репозитория или пакетного менеджера завершается явной диагностикой; системные RPM не включаются внутрь ZIP WebAssistant.

Затем установщик:

- создаёт системную группу и пользователя `webassist`, если они отсутствуют;
- добавляет учётную запись службы в доступные группы сканеров;
- устанавливает приложение в `/opt/webassist`;
- использует упакованный `appsettings.json` без замены;
- создаёт каталоги состояния времени выполнения;
- устанавливает `webassist.service`;
- выполняет перечитывание конфигурации systemd;
- включает и запускает `webassist.service`;
- с закрытием при неопределённости проверяет активность службы.

## Состояние времени выполнения

```text
application: /opt/webassist
logs:        /var/log/webassistant
data:        /var/lib/webassistant
unit:        /etc/systemd/system/webassist.service
```

`/var/lib/webassistant` остаётся каталогом состояния и домашним каталогом системной учётной записи `webassist`; это не автоматическая область полномочий файлового обмена. Файловые корни определяются только явно настроенными элементами `WebAssistant:FileSystem`, и браузерный API не может менять их физические пути.

`/var/log/webassistant` и `/var/lib/webassistant` принадлежат учётной записи службы и по умолчанию сохраняются при удалении.

Служба слушает только loopback `127.0.0.1`; порт по умолчанию — `17654`.

## Проверка

Состояние службы:

```bash
systemctl status webassist.service
```

Проверка состояния HTTP:

```bash
curl http://127.0.0.1:17654/v1/health
```

Остановка, запуск и перезапуск выполняются стандартными командами systemd:

```bash
sudo systemctl stop webassist.service
sudo systemctl start webassist.service
sudo systemctl restart webassist.service
```

## Подключение сетевых сканеров

Администратор обеспечивает доступность МФУ по сети, включает поддерживаемый WSD/eSCL, при необходимости настраивает DHCP/DNS, VLAN, межсетевой экран и нестандартные драйверы. WebAssistant устанавливает стандартную среду выполнения SANE/AirScan и работает от отдельной учётной записи службы. Установка не требует наличия подключённого сканера и не изменяет системную конфигурацию SANE вручную; настройки устройства остаются у администратора.

Если сканер не появился в диагностической панели, проверьте от имени администратора:

```bash
rpm -q sane-airscan
scanimage -L
airscan-discover
sudo -u webassist scanimage -L
```

### Проверка зависимостей

Установщик проверяет динамические зависимости (`ldd -r`), загрузку библиотеки от имени `webassist` через `dlopen(RTLD_NOW)` и экспортируемые точки входа SANE через `dlsym`. Для прямой проверки используется штатный Python 3 с `ctypes`; если он отсутствует, установщик устанавливает пакет `python3` и повторно проверяет наличие модуля. Python не требуется для работы службы. Если отсутствует команда `runuser`, необходимая для смены учётной записи, установщик устанавливает штатный пакет `util-linux` и повторно проверяет наличие команды. Проверка не вызывает функции SANE и не запускает поиск устройств. При отказе установщик указывает этап, путь библиотеки, учётную запись и сообщение загрузчика. Это не подтверждает, что драйвер активирован или что устройство доступно. Установщик не определяет действующую регистрацию по содержимому файлов от имени root и не включает драйвер самостоятельно.  

### Сохранение административской конфигурации

SANE 1.4.0 может читать даже файлы с суффиксом `.rpmnew` в `dll.d`. Если до пакетной операции установщика существовал штатный файл `dll.d/airscan`, проверяются его содержимое, владелец, группа и права после операции; вновь созданный `dll.d/airscan.rpmnew` сохраняется в скрытом каталоге `dll.d/.webassistant-airscan-rpmnew.*` независимо от синтаксиса исходного файла. Путь сохранённой копии выводится при установке. Если конфликтующий файл уже существовал, в том числе после прерывания установки или отказа перемещения, установщик завершает работу с ошибкой даже при установленном пакете. Администратор должен согласовать конфигурацию и сохранить конфликтующую копию вне `dll.d` перед повторным запуском. Не копируйте такой файл обратно в `dll.d`, если драйвер должен оставаться отключённым.

### Восстановление после отказа пакетной операции

Перед обращением к apt-rpm установщик создаёт защищённый каталог `/etc/sane.d.webassistant-airscan-pending` с исходными метаданными и контрольной суммой регистрации в `registration-before` (пустое свидетельство означает отсутствие исходного файла). При ошибке проверки или прерывании каталог сохраняется и блокирует любой повтор даже при установленном RPM и отсутствии `.rpmnew`. Установщик не восстанавливает административские файлы автоматически. Администратор должен сопоставить сохранённое состояние с фактическими содержимым и правами, восстановить исходные ограничения из своей резервной копии либо явно согласовать новые, разрешить конфликт RPM-копии и только затем удалить свидетельство (каталог целиком) и повторить установку. Не удаляйте его только ради обхода ошибки. Повреждённое свидетельство также требует ручной проверки. Не выполняйте параллельные пакетные операции или изменения этой конфигурации во время установки. При уже работающей службе и других потребителях SANE автоматической изоляции нет: временная RPM-копия может быть видима до завершения архивирования, а при отказе — до вмешательства администратора. При необходимости остановите такие потребители перед установкой.

### Диагностика устройства

Проверьте регистрацию airscan в настройках SANE (dll.conf и dll.d), настройки обнаружения и сеть. Если утилита обнаружения показывает устройство, а SANE не перечисляет его, администратор может добавить точную строку из вывода airscan-discover в секцию [devices] файла /etc/sane.d/airscan.conf, предварительно сохранив резервную копию и существующие записи. Не заменяйте весь файл и не отменяйте явно заданные ограничения.

После изменения системной конфигурации SANE перезапустите службу, затем проверьте список:

```bash
sudo systemctl restart webassist.service
curl http://127.0.0.1:17654/v1/scanners
```

Выберите устройство в диагностической панели и нажмите «Получить возможности». Это не запускает сканирование. Для независимой проверки возможностей используйте scanimage с точным именем устройства из списка и параметром --all-options от имени webassist.

Обнаружение, чтение возможностей и физическое сканирование — отдельные проверки. Пустой список не означает неисправность WebAssistant; ошибка sane_start или DeviceCommunicationException не доказывает конкретную физическую причину. Для приёмки сканирования отдельно требуется успешное получение PDF.

## Удаление

Из распакованного канонического пакета:

```bash
sudo ./uninstall.sh
```

По умолчанию удаляются unit, установленное приложение и учётная запись службы, но сохраняются:

```text
/var/log/webassistant
/var/lib/webassistant
```

Для явного удаления состояния времени выполнения используется:

```bash
sudo ./uninstall.sh --purge-data
```

## Граница доказательств

Канонической целевой средой остаётся ALT Linux 10.1. Автоматизированное выполнение в другой среде ALT может быть полезным регрессионным доказательством механики пакета и systemd, но не заменяет приёмку именно на ALT Linux 10.1.
