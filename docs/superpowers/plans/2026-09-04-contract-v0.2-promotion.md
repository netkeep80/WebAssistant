# WebAssistant v0.2 Contract Promotion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote `webassistant-contract/v0.2` and `webassistant-conformance/v0.2` as the new accepted semantic baseline without changing observable product behavior, while preserving immutable v0.1 artifacts and keeping governance/non-governance transactions isolated.

**Architecture:** Implement three repository transactions in order: A makes `BaselineContractTests` resolve the current pair from `repo-policy.json`; B prepares root README references; C atomically creates v0.2 contract/conformance artifacts and switches `repo-policy.json` current selection under a dedicated GovernanceGrant. Each implementation branch starts from fresh `main`; the planning branch is reference-only and must not be used as an implementation base.

**Tech Stack:** .NET 10, C# xUnit, JSON contract/conformance artifacts, `repo-policy.json`, GitHub Actions (`ci-required`, `repo-guard`), GitHub PR/Issue governance.

**Spec:** `docs/superpowers/specs/2026-09-04-contract-v0.2-promotion-design.md`

## Global Constraints

- Repository: `netkeep80/WebAssistant`; GitHub `main` is source of truth.
- Planning reference branch: `design/contract-v0.2-promotion`; implementation branches MUST start from fresh `main`, not from the planning branch.
- Accepted v0.1 artifacts are immutable: do not edit `contracts/webassistant-contract-v0.1.json` or `contracts/webassistant-conformance-v0.1.json`.
- Transaction A may touch only `tests/core/BaselineContractTests.cs`.
- Transaction B may touch only `README.md`.
- Transaction C may touch only `repo-policy.json`, `contracts/webassistant-contract-v0.2.json`, and `contracts/webassistant-conformance-v0.2.json`.
- Transaction C requires a linked GovernanceGrant authorizing exactly those three governance paths and `allow_policy_relaxation: []`.
- No product source, workflow, package/install script, or product documentation under `webassist/**` changes are allowed in this promotion sequence.
- No implementation of #98, #99, #94, or #6 is included.
- Preserve the accepted capability-scoped scanner boundary: physical acquisition -> all acquired pages -> one raw `application/pdf` -> caller handoff -> scanner operation ends.
- `raw PDF` excludes semantic post-acquisition document processing but allows encoding/compression/PDF packaging needed to represent acquired pages.
- Future independent edit/OCR/signing/upload/auth/file capabilities remain allowed only through separate contract/conformance changes.
- Before every merge: fresh `main`, exact head, `behind_by=0`, `repo-guard` GREEN, `ci-required` GREEN, no unresolved review blockers, fixed `expected_head_sha`, then post-merge fresh-main reread.

Add these helpers and record inside the same test class:

```csharp
private static CurrentPairPaths ResolveCurrentPairPaths(JsonElement policyRoot)
{
    var current = policyRoot
        .GetProperty("contract_conformance")
        .GetProperty("current");

    return new CurrentPairPaths(
        Assert.IsType<string>(current.GetProperty("contract").GetProperty("path").GetString()),
        Assert.IsType<string>(current.GetProperty("conformance").GetProperty("path").GetString()));
}

private static string NormalizeRepositoryPath(string path) =>
    path.Replace('\\', '/').TrimStart('/');

private static string ToPlatformPath(string path) =>
    NormalizeRepositoryPath(path).Replace('/', Path.DirectorySeparatorChar);

private sealed record CurrentPairPaths(string ContractPath, string ConformancePath);
```
