# Производительность CI — #332

## Первый этап: независимые платформенные испытания ALT

Обычная приёмка и приёмка установочных артефактов используют два независимых задания матрицы `platform: [p10, p11]`. Каждое получает один и тот же неизменяемый ZIP из сборочного задания, проверяет его SHA-256 и происхождение, затем исполняет свою часть исходного сценария. Отказ или отмена любой обязательной части блокирует итоговый `ci-required`. Автоматическая отмена второго задания при отказе первого отключена для сохранения диагностики.

`ALT_ACCEPTANCE_SCOPE=all` — прежний последовательный локальный сценарий (по умолчанию); `p10` — пакетная приёмка, `p11` — полный жизненный цикл systemd. Другие непустые значения отклоняются. Отдельные задания не сообщают об успехе полного последовательного сценария.

`ALT_TIMING_BEGIN` и `ALT_TIMING_END` фиксируют длительность платформенных фаз и сборки образа p11; отметка окончания выводится только после успешного выполнения соответствующей фазы. Для оценки отказов и отмен используется время задания в журнале Actions. Сравниваются длительности обоих заданий и критический путь, а не сумма времени runners. Пределы 45/60 минут для двух путей приёмки сохранены.

## Последующие этапы

Подготовка доверенных образов ALT и сохранение скачанных RPM с согласованными индексами (без предварительной установки проверяемых зависимостей) являются отдельной транзакцией. Требуется доказать эквивалентность реальной установки, целостность и свежесть, обработку отсутствующего или повреждённого кэша и отдельную проверку актуальных официальных источников. В первом этапе источники пакетов, образов и установщик не изменяются. Физическая приёмка ALT Linux 10.1 не заменяется контейнерными проверками.

Целевое время полного прогретого CI — 5–8 минут; до сравнительных измерений это только ориентир.

## R2b1 — локальная упаковка и полная приёмка

Принятое исследование R2a (#335) доказало автономную установку p10/p11 (555→29 с и 782→20 с). R2b1 переносит его прокси и тесты без изменений, а полный действующий сценарий приёмки выполняет дважды: с записью запросов, затем с воспроизведением из нового слоя над точным исходным образом. Общий ZIP проверяется существующим потребителем. Sidecar с сетевым режимом none сохраняет изолированное сетевое пространство при перезапуске p11; только записывающий прокси хоста имеет доступ к официальному репозиторию. Временный образ содержит снимок, а не предустановленные продуктовые зависимости; проверяются слои, совпадение RPM inventory исходного и упакованного образов, docker save/load и точные байты снимка. Полная приёмка повторяет все исходные проверки и сравнивает списки RPM в трёх контрольных точках. Вне явного режима кэша остаётся исходный онлайн-путь.

Новый workflow только для проверки PR, без packages:write. Локальный образ и RPM не выгружаются, сохраняются небольшие свидетельства. Это ещё не промышленная публикация GHCR, не доказательство свежести и не переключение обязательных проверок. Дальше отдельно проверяются права распространения, доверенный producer, digest пары, свежесть и потребление.
